# Reusable AI prompt — UX Screens 2 (desktop-only)

Use this document when generating **one** ISIPPE-3 / ACA ORS screen from a PNG in [`UX Screens 2/`](../../UX Screens 2/) (also linked as [`design/screens`](../../design/screens)).

Every PNG is **1536×1024** and contains:

| Region | Approx. width | What it is |
|--------|---------------|------------|
| **Left** | ~58–62% | Desktop product UI — **source of truth** |
| **Right** | ~38–42% | Phone mockup in a device frame — **ignore chrome**; use only as a mobile stacking hint |

Build **one** responsive React page per PNG. Never recreate the handset, notch, status bar, or dual-layout collage.

For cleaner attachments, prefer cropped desktop images in [`design/desktop/`](../../design/desktop/) (generated by `npm run design:crop` from `ors-web`).

## Project context (always include)

- App: `ors-web/` — Vite + React + TypeScript + Tailwind + React Router + lucide-react + **react-i18next**
- Tokens: [`tailwind.config.ts`](../tailwind.config.ts) — blue `#0B45E0`, navy `#0A2A7A`, green `#0B7A3B`, red `#D7263D`, ink `#0F1B3D`, mute `#5B6685`, soft `#EEF3FF`, Inter; cards `rounded-lg` + `border-slate-200`
- UI kit: `src/components/ui` — Button, Card, Field, Input, Select, Toggle, Pill, Tabs, Stepper, Table, Stats, Donut, BarList, Modal/BottomSheet, KV, Pagination
- Layouts: `PublicLayout`, `ParticipantLayout`, `AdminLayout`
- i18n: `src/i18n/` + `src/locales/{en,sw}/*.json` — use `useTranslation()` / `t()` for all user-visible copy; brand names (ACA, ISIPPE-3, KICC) may stay literal
- Images: `public/placeholders/*` or `public/assets/*` with `alt` text
- Data: mock only in `src/data/*.ts` (IDs/amounts/routes); labels via locale keys or `useEventCopy()`; interactive controls must work

## Master prompt (copy-paste)

Replace bracketed fields, attach the PNG (prefer `design/desktop/…` if available), then run.

```text
You are implementing ONE screen of the ISIPPE-3 (Anti-Counterfeit Authority) Online Registration Portal.

STACK
- Vite + React 18/19 + TypeScript
- Tailwind CSS (tokens in tailwind.config.ts)
- React Router, lucide-react, react-i18next
- Existing UI kit: Button, Card, Field, Input, Select, Toggle, Pill, Tabs, Stepper, Table, Stats, Donut, BarList, Modal/BottomSheet, KV, Pagination
- Existing layouts: PublicLayout | ParticipantLayout | AdminLayout (use the correct one)
- i18n: add/update keys in src/locales/en/*.json (and sw when translating); call useTranslation() — no hardcoded English UI strings except brand names

ATTACHED DESIGN
- File: [e.g. design/desktop/Screen A.png OR UX Screens 2/Screen A.png]
- Route to implement: [e.g. / ]
- Layout wrapper: [PublicLayout | ParticipantLayout | AdminLayout | none]

CRITICAL — HOW TO READ THE PNG
1. If the file is from UX Screens 2/ (full export): it has TWO canvases side by side:
   - LEFT = desktop UI (source of truth for layout, spacing, type, colour, copy, icons).
   - RIGHT = phone mockup inside a device frame (IGNORE the device chrome entirely).
2. If the file is from design/desktop/: it is already the LEFT desktop crop only — match it fully.
3. Do NOT recreate the phone handset, notch, status bar, home indicator, or any “desktop + phone collage” layout.
4. Build a SINGLE responsive page:
   - Desktop (lg/xl ≈ 1280px): match the LEFT canvas (or desktop crop) pixel-faithfully.
   - Mobile (base ≈ 360px): use the RIGHT canvas content hierarchy (if present) as a stacking guide only — order of blocks, not the phone UI chrome.
5. For full exports: crop mentally — treat everything to the right of the vertical split (where the phone begins) as non-UI. If unsure, prefer the left ~58–62% of the image.

DESIGN TOKENS (do not invent a new palette)
- blue #0B45E0, navy #0A2A7A, green #0B7A3B, red #D7263D
- ink #0F1B3D, mute #5B6685, soft #EEF3FF
- Font: Inter
- Cards: white, rounded-lg, 1px border slate-200
- No decorative waves, skewed sections, or “AI purple gradient” looks. Rectilinear layout only.

FIDELITY RULES
1. Match spacing, radii, typography scale, icon style, labels, and copy from the desktop canvas. Do not invent marketing copy.
2. Match component structure section-by-section (header → hero/content → secondary bands → footer if shown).
3. Photos: use public/placeholders/* or public/assets/* with meaningful alt text. Do not leave broken images.
4. Every control visible on the desktop canvas must work with mock data (tabs, filters, accordion, stepper, modal, pagination, toggles).
5. Accessibility: semantic HTML, labelled inputs, visible focus, aria-* where needed, 4.5:1 contrast.
6. Mobile-first Tailwind: base = phone stacking; md:/lg: = tablet/desktop. No horizontal page scroll at 360px. Tables → overflow-x-auto or stacked cards on mobile. Admin sidebar → bottom nav / drawer on mobile (already in AdminLayout).
7. Reuse UI kit and layouts — do not duplicate Button/Card/Table markup.
8. i18n: put user-visible strings in locale JSON with semantic keys (e.g. home.hero.registerCta). Use t() / useEventCopy() / formatMoney|formatDate. Never concatenate translated fragments; use interpolation. Seed English first; Swahili may fall back until translated.

WORKFLOW (mandatory)
1. Open the attached PNG. Explicitly list the desktop (LEFT) sections top-to-bottom (bullet list).
2. Note which parts belong only to the phone mockup and will be ignored (if full export).
3. Implement the page for the given route using the correct layout.
4. Self-check at 360px, 768px, and 1280px against the desktop canvas.
5. Run: npx tsc --noEmit && npm run lint
6. Summarise: sections built, files touched, anything the PNG was ambiguous about.

OUT OF SCOPE
- Do not build other screens in this run.
- Do not redesign or “improve” the UX.
- Do not implement the phone frame.
```
